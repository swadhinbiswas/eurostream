Frequently asked questions about EuroStream and the patterns it demonstrates.
These mirror the questions interviewers actually ask.

## Product & scope

### Is EuroStream a production system?

It is a **reference architecture that runs like one**. SQLite doesn't shard
and DuckDB doesn't serve concurrent writers — by design. Every component
hides behind the interface its production counterpart uses
(`Producer`/`Consumer`, standard SQL, DAG tasks), so scaling is a wiring
change. [The production playbook](/deep-dives/production-playbook) details
exactly what you swap.

### Why simulated sources instead of real APIs?

Determinism and focus. Faker-generated EU data (IBANs, country codes,
consent flags) makes the demo reproducible run-after-run, which is what makes
the erasure verification trustworthy — and keeps the project about the
platform, not about scraping credentials.

## GDPR mechanics

### How is Article 17 erasure proven?

Every execution appends a JSONL record and a warehouse row containing the
request ID, customer ID, layers touched, timestamps, status and
`sha256(request_id:customer_id)[:16]`. The hash lets a DSAR team demonstrate
a specific request executed against a specific subject **without** storing
anything reversible.

### What happens to rows in Bronze after erasure?

They survive with every PII column replaced by `<anonymized>`. Deleting raw
rows would destroy event history for analytics; anonymizing destroys the
personal data while preserving the shape of the dataset. Silver and Gold rows
for the subject are deleted outright because they're derived data.

### How fast must erasure complete?

Configurable via `EUROSTREAM_ERASURE_SLA_SECONDS` (default 60). Each
execution records its latency into a histogram metric and increments an
`erasure_sla_breach` counter when over SLA — SLAs you don't measure are
marketing copy.

## Implementation choices

### Why pure Python instead of Spark/Flink?

Because the *architecture* is the portfolio piece, not the cluster. Windowed
rules map 1:1 to Spark Structured Streaming semantics (rolling windows,
per-key state, watermark-ish expiry), so the port is mechanical. Running the
same logic locally means every interview claim is verifiable on demand.

### How does the fraud scorer avoid duplicate alerts?

Each rule fires once per customer per window: velocity alerts exactly at
`threshold + 1` payments, geo-mismatch only on the first mismatching payment
in a window. Alert spam trains analysts to ignore alerts.

### Where does the PII salt live?

`EUROSTREAM_PII_SALT`, defaulting to a public dev value. Production loads it
from a secret manager — and rotating it invalidates existing Silver hashes,
which is why both hashing implementations (SQL and Python) share one scheme
with a test pinning them together.
